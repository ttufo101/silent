# TDesign for mobile

## Overview

本文件来自 Figma 文件 `YXoHhILuoPRdsrz68TOclt` 的结构化变量和本地样式，当前主题为 **dark**。
它面向移动端产品，强调清晰的信息层级、触控友好的尺寸体系和一致的状态反馈。

机器可读 YAML 是规范值；下方说明用于解释使用方式。完整 Figma ID、mode、scope、code syntax 和 alias 保存在 .design-md/figma-source.json。

## Layout

间距 Token 来源于 size 尺寸 Collection，包括基础尺寸、组件高度、组件 margin、padding 和弹出层 padding。
优先使用语义化的 padding/margin Token；仅在没有合适语义 Token 时使用基础 size-*。

## Elevation & Depth

阴影来自 Figma Local Effect Styles。多层阴影必须保持原顺序。

- **Shadow/Shadow-1 基础投影：** `0px 2px 4px -1px #0000001F, 0px 4px 5px 0px #00000014, 0px 1px 10px 0px #0000000D`
- **Shadow/Shadow-2 中层投影：** `0px 5px 5px -3px #0000001A, 0px 8px 10px 1px #0000000F, 0px 3px 14px 2px #0000000D`
- **Shadow/Shadow-3 上层投影：** `0px 8px 10px -5px #00000014, 0px 16px 24px 2px #0000000A, 0px 6px 30px 5px #0000000D`

## Components

本规范不从 Figma 提取组件实现。组件 Props、Variant、Size、DOM、状态和可访问性行为以项目源码为事实来源。
对于 shadcn/ui 项目，应读取 components.json、globals.css 和 components/ui；DESIGN.md 只约束全局视觉 Token 和使用原则。

## Do's and Don'ts

- 应优先使用语义颜色 Token，再使用数字色阶。
- 应将字体、字号、字重、行高和字距作为完整文字样式应用。
- 应保持多层阴影顺序和透明度。
- 应在主题切换时使用对应的 DESIGN.md 文件。
- 不应在组件内新增已有 Token 可以表达的硬编码颜色或尺寸。
- 不应把 light 数字色阶直接复用为 dark 主题值。
- 不应根据截图估算结构化变量中已经存在的设计值。
